국문 요약

제품 한 문장. 당사국 한 나라의 기후 기록(조약 지위 · 법령 · 기관 · NDC · BTR · 규제 파라미터)을 문장 · 셀 · 해시 영수증과 함께 정본화하고, 쓰는 순간 근거가 붙고, 근거 없으면 막히고, 개정이 오면 무엇이 흔들리는지 알리는 런타임입니다. 판정은 언제나 사람이 합니다. 등급 · 순위 · 추정 · 자동 판정은 만들지 않습니다.

  • 구조: 4층 — L0 정본 그래프, L1 살아있는 기록(스냅샷 diff), L2 저작 검증(핵심 제품), L3 연합(2국째부터, 레포 밖).
  • 파일럿: 캄보디아 KHM, 화면 2+1장(원장 · 근거 서랍 · Word 왕복 저작). 격차표는 비목표, 모니터링은 내부 뷰로 강등.
  • 규율: 철칙 R1~R16과 아키텍처 결정 AD-1~13 — 전부 문서 규칙이 아니라 CI가 기계로 막습니다. 인스턴스 하드코딩 0, 어휘는 시드 CSV 단일 정본, 발행 경로에 사람 머지 없음, 알림은 메일이 아니라 운영자가 실제로 여는 곳(broken.md)으로.

Chapter 1Product definition

In one sentence. A runtime that canonicalizes one Party's climate record — treaty status, legislation, institutions, NDC, BTR, regulatory parameters — with sentence-level, cell-level and hash-level receipts, so that evidence attaches at the moment of writing, writing without evidence is blocked, and when an amendment arrives the runtime reports exactly which claims it shakes. Judgment is always human.

What this product is not. It produces no ratings, no rankings, no estimates and no automated judgments. It makes no "first in the world" claims; where differentiation matters, it is phrased as a question for the counterpart to answer, never as an assertion. Cross-country transition features (A→B gap tables) are an emergent capability from the second country onward and are an explicit non-goal of the pilot.

Honest maturity. As of 2026-10-16 all ten work packages are delivered: a deterministic global graph over 200 recorded countries, generated views, a statically built 1,761-page site, the authoring verifier (deterministic ⟦iso3:doc_id⟧ citations, .docx in → Word comments out, byte-identical reruns), the structural diff, and the launch checklist — with every iron-rule mutation detected by the test harness. Not yet done, by design: deployment (the owner's act, single CI path prepared inert), the five P0 demand interviews, and a human check that Microsoft Word opens an annotated draft (machine validation only so far — disclosed in the authoring docs). This label is updated at every stage and never overstated.

Chapter 2Pilot scope & users

Pilot country: Cambodia (KHM) — the predecessor system's deepest coverage, a submitted BTR1, and existing teaching material. The official English editions of Cambodian documents are the canonical inputs; Khmer editions are retained by file hash only (AD-3).

Users. Party climate teams and the institutions that support them. The core user task is authoring: writing a report sentence and learning, before submission, whether it is anchored, outdated, or unsupported.

Pilot surface: 2+1 screens (AD-9): the ledger, the evidence drawer, and the authoring path (.docx round-trip, Chapter 8). Monitoring is demoted to an internal operations view; the practitioner-facing channel is an email digest generated from build diffs, with deep links. The gap table is recorded here, canonically, as a pilot non-goal. Any screen beyond these requires a passed KHM practitioner task test — that gate clause is part of this canon.

Demand evidence. Five P0 demand interviews run in parallel with development; the questionnaire centers on the authoring tool. Testimonials follow the evidence rule: real ones only — currently zero, so testimonial space stays empty.

Chapter 4Canonical records & anchors

The anchor's canonical unit (AD-3) is: source-file SHA-256 + page + a human-confirmed quotation + the version of the normalization rules. It is not a hash of an extracted sentence — extraction from scans and Khmer text is non-deterministic, so the canonical unit must not depend on it.

Receipt formats. The first-class receipt formats include page image + coordinate box (AD-4), so receipts survive scanned and Khmer documents. If this proves infeasible during the pilot, legislation leaves pilot scope and that fact is written into this canon — scope honesty over silent degradation.

Four evidence states, and refusal. Every published value is either anchored or carries one of four states with a reason; refusal (a source declined, a value withheld) is first-class content, not an error state.

observed — filled pledged — dashed unknown — hatched, reason attached absent — explicit absence

Numbers only via census keys (R6). Every figure in any document or screen must carry a machine link to a census key. The check runs in reverse: the scanner sweeps all numbers and fails CI on any number without a link — the predecessor only cross-checked numbers that were already linked, and three kinds of figures rotted unnoticed.

Anchor bytes are preserved (R12). The original bytes an anchor points at live in durable storage (e.g. release assets) under a retention policy with a per-country cap and a stated retention period. A CI cache with a 7-day TTL and someone's laptop are not preservation.

Chapter 5Vocabulary & seeds

Single canonical source: seed CSVs (R2). All vocabulary — zod enums, TypeScript types, API vocabulary — is code-generated from the seed (seed → generated/vocab.ts). Hand-written vocabulary enums are banned and caught by grep; the codegen output directory is never hand-edited.

Zero instance hardcoding (R1). Engine code contains no ISO3 codes, no country names, no document-ID literals. All country-specific logic is supplied by seeds and data. The lint greps engine/ and fails CI on sight. The precedent this rule exists to prevent: the predecessor shipped iso3 === 'KHM' in its compose step, and the pilot country survived on frozen hardcode.

Seed layering follows the SSRND ontology method: L2 taxonomy (is-a, natural kinds only), L3 terms (source definitions verbatim), L4 attributes bound to classes, L5 units, L6 relations, L7 facets with per-value evidence. The platform seed is semver-versioned; country seeds live under countries/<ISO3>/ and reference platform IDs only — never commit hashes or line numbers, which rot silently.

Seed checking runs the SSRND checkers in place (check_ontology_seed.py, cq_check.py with competency questions); acceptance for the platform seed is zero errors and all competency questions passing.

Chapter 6Sources & ingestion

Adapters (pilot): UNFCCC registry, BTR submission list, UNTC treaty status. Every fetch lands as a snapshot with a SHA-256 manifest; on failure the previous snapshot stays current. Adapters are country-agnostic — the per-country document list is supplied by the seed (R1). NDC document bytes keep the predecessor's mirror discipline — a mirrored copy counts only when its hash is cross-checked against an independent archive capture — and that verification carries into WP-03.

Success is judged by bytes, not status codes (R14): hash, a size floor, and a format check. The measured failure mode this guards: unfccc.int returns HTTP 200 with a 212-byte bot-check page — a "successful" fetch that is actually an outage.

Staleness budget in the contract (R14). Every source contract declares its maximum tolerated age. A source over budget surfaces as first-class status on affected records and public screens ("this source unresponsive for N weeks") — staleness is shown, never hidden.

Legislation is a separate promise (AD-13). Until a named source, a named cadence and a Khmer-capable pipeline exist, legislation nodes are declared manual · as-of dated · quarterly review, and screens show that tier as-is. No automated-freshness promise is made that no adapter can keep.

Licensing. No external asset is used before it is entered in the license register (OECD and Climate Policy Radar terms verified against the actual documents first). Summaries only; clause text is never stored verbatim.

Chapter 7Build, derivation & gates

Publish-blocking gates. A build either satisfies every gate or writes no output file at all (R5): every published value anchored or reasoned (four states), derived values stored apart from base (R3), machine processes never emit judged values (R4), graph vocabulary ⊆ seed, numbers reconciled against census keys (R6).

Mutation doctrine. Every iron rule is paired with a mutation test that deliberately violates it. If the violation goes undetected, the test is fixed — the rule is never lowered. A gate that cannot catch its own violation is treated as broken.

Golden files (R7). Golden updates go through a dedicated script that prints a diff summary and requires an approval reason string. Error messages never print the copy command — a test whose failure message teaches you how to overwrite it is a rubber stamp.

Chapter 8Authoring verification (L2)

Deterministic citation grammar, not NLP (AD-1). The only sentences that receive verdicts are those that explicitly cite an anchor:

The revised NDC commits to a 41.7% reduction by 2030 ⟦khm-ndc-2020-p12-s3⟧.

Parsing is deterministic; the same input always yields the same verdict (R10, enforced by a reproducibility test). Sentences without a citation are all flagged unanchored — that flag is itself a useful output, not a failure of the tool. There is no free-text claim extraction. An LLM may run beside the judgment path, producing a "this sentence could cite this anchor" suggestion report; it never enters the verdict.

Word round-trip (AD-2). Practitioners upload a .docx; the runtime extracts sentences and anchor tokens deterministically and returns verdicts as a Word comment layer. The practitioner never leaves Word. The web paste-in panel is a demo and short-text aid only.

Hard edges. A sentence containing a figure with no anchor cannot pass author-check. And when stale claims exceed 10% of the graph, author-check switches itself to verification unavailable (AD-12) — it refuses to approve drafts against a graph it knows is outdated.

Chapter 9The living record: snapshots & diffs

asOf = snapshot selection (AD-5). Every build is an immutable, hash-stamped snapshot; reconstructing the record "as of" a date means selecting a snapshot. Node-level bi-temporality is abandoned as unmaintainable by one person; effectivity attributes exist only for two or three classes (treaty status, legal instruments).

No stored re-evaluation queue (R9). A stored queue is a merge backlog under another name — the predecessor's queue proved it. Staleness is computed: full rebuild, then a structural diff against the previous snapshot. The diff is the work list.

Diff reports. When an amendment is injected, the runtime reproduces the list of shaken claims (WP-09 acceptance). Practitioners receive it as an email digest with deep links.

Backlog has an automatic ending (AD-12). Pending diff verdicts carry a 14-day SLA. Beyond it, the public screen automatically shows "this record is N days behind" at the top. Queue depth and oldest-item age are internal monitoring metric #1. Flags that can be ignored forever train people to ignore them — so these cannot be.

Chapter 10Publication & operations

Why this chapter is strict. The operations lens of the adversarial review measured the predecessor live: the same chain — scheduled ingest → human merge → CI deploy → daily monitor — collapsed across its entire length within four weeks of being declared done and green. Refresh failed three consecutive weeks; the one successful PR sat unmerged for 31 days (merge rate 1 of 5); operators bypassed the CI gate with manual deploys; failure emails went unanswered for three weeks; the monitoring issue was permanently red, so the signal was dead. Every rule below exists because of a measured failure, not a hypothetical one.

Humans are removed from the publish path (AD-11). A rebuild that passes all gates (R1–R16) merges and deploys automatically. Human review is invoked only for changes the gates blocked. Deploy credentials exist only as CI secrets, so manual deploys are physically impossible, not merely discouraged (R8 — one deploy path; no manual deploy command is documented anywhere). The public footer prints its build commit hash, and a daily watchdog compares that hash with main HEAD — mismatch is an incident.

Alerts land where the operator actually looks (R13). Failures are written automatically into the operations ledger (99-ops/broken.md, one daily digest). Email does not count as a destination. A check red for more than 7 days is demoted from "alert" to "accepted defect" and moved to the ledger — only new failures make noise.

Dead-man switch and as-of (R16). Every scheduled job carries an external heartbeat ping that alarms through a non-operator channel when it stops. Every public screen shows its record date (as-of) permanently — a stall is visible to readers before operators. The design assumes the host platform disables schedules after 60 days of repository inactivity.

Dependency hygiene (R15). No beta or RC dependencies. Lockfile-exact installation (npm ci-equivalent) passing in CI is a merge condition; an install that does not reproduce across machines is itself a registered defect.

Chapter 11API & frontend

API = static JSON generated at build time (/api/v1/*.json, AD-6). No server runtime. The frontend reads only the view JSON produced by the graph reader — never record files, never seeds (R11, enforced by an import-path lint). Framework: a stable-release static generator (Vite or Astro); introducing a server runtime would be a separate decision.

The one visitor action: click a number, and its receipt opens — document page, sentence, hash. Everything on the page exists to make that action happen.

The first three seconds, zero clicks (AD-10): country name, treaty status in one line, countdown to the next deadline. Completeness is shown as a segmented strip by state — evidenced n · unknown n · absent n — never an aggregate percentage, and never a gauge; a gauge is a score grammar wearing a different name. The strip's heading is "what this runtime has read so far": absence is attributed to the runtime, not to the country.

Receipts are addressable. Every receipt panel has a unique URL from day one.

The three-minute demo path is a fixed design deliverable, deep-linked at every step:

  1. Open the ledger.
  2. Click a number.
  3. See the receipt: document page, sentence, hash.
  4. The reviewer pastes their own sentence into the authoring check.
  5. The verdict comes back: anchored, outdated, or unsupported.

Performance floor (P-F10): server-rendered static HTML baseline, no WebGL, and a 3G throttle test in CI — the audience includes low-bandwidth, older devices.

Visual vocabulary. UN blue, no black — the predecessor's final art direction. The token canon is the VC house kit: its neutrals, three typefaces, motion eases, light-only mode and line-over-box discipline, with the kit's own rule that each product swaps only the accent family. A read of the kit (2026-10-15) confirms it defines no UN-blue accent and no visual grammar for the four states or for refusal — those are new token specifications this product adds on top of the kit, with the four-state semantics sourced from the predecessor's production schema. The states render as in Chapter 4's legend; refusal is first-class content. Motion follows the evidence chain (value → document → hash) and no count-up animation ever plays on a figure without a receipt. Hero copy obeys the same evidence discipline: every number in it carries a census key.

Build order: the eight frontend roles (strategist → reference hunter → design system → hero → sections → motion → performance → launch checklist) run in order; the launch role produces a checklist only — deployment is done by the owner (Chapter 14).

Chapter 14Risks, open decisions & governance

Awaiting an owner decision (blocking where noted)

  1. The www-grade site: clean up / rebrand. Precondition for the first KHM demo — the same brand currently serves a product with the opposite philosophy.
  2. The predecessor's evidence-graph branch: it grows inside a frozen repository and shares the product's name-space; the climate ontology canon points at it, so a migration path must be decided together with its deletion.
  3. Repository name & URL — decided 2026-10-15: the repository lives at github.com/HarimJung/Gaia-Visual-Climate-Ontology (public), and that URL is stamped on page 1 of this blueprint. The name is separate from Watch. Record Runtime remains the product's working display name.

Governance. Publishing, sending, deploying and submitting are done by the owner personally; this system produces drafts and queues, nothing further. The predecessor repository is frozen: read-only, no branches, no code copied — patterns only. The UN track and the investment track never share material (brand wall).

Language discipline. No ratings, rankings, estimates or automated judgments. No "world first" phrasing; differentiation claims appear only in question form. Maturity labels are honest and updated per stage. Every number in every published surface carries a census key (R6).

Risk register (summary). The full adversarial ledger is Annex C. The three structural risks this design hedges: (1) operational decay — hedged by removing humans from the publish path, dead-man switches, and alerts that land where the operator looks; (2) evidence rot — hedged by reverse number-checking, durable anchor-byte storage, and staleness budgets; (3) scope creep — hedged by canonical non-goals, the screen-gate clause, and the L3 exclusion.
